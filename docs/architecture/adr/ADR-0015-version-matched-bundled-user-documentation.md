# ADR-0015: Version-Matched Bundled User Documentation

## Status

Accepted

## Context

`vi-history-suite` now has a governed wiki derived from the repository
documentation package, but extension users still had to reach outside the
installed product to read that guidance.

That creates three problems:

1. review guidance depends on repo or wiki access even when the user already
   has the installed extension
2. extension panels cannot point users to a version-matched local docs surface
   inside the installed build
3. future documentation delivery would drift unless the packaged-doc surface is
   governed from the same publication state as the wiki

The repo already retains:

- `docs/product/wiki-authority-map.md`
- `docs/product/wiki-seed-plan.md`
- `docs/product/wiki-publication-ledger.md`

The remaining gap is a packaged user-doc surface that can ship with the VSIX.

## Decision

The repo will ship a version-matched bundled user-documentation pack inside the
extension package.

That pack is governed as a derived surface from the published wiki set:

- the machine-readable publication state lives in
  `docs/product/wiki-publication-ledger.json`
- the packaged bundle is generated by `npm run docs:bundle`
- generated artifacts live under `resources/bundled-docs/`
  - `manifest.json`
  - `pages/*.html`

The extension exposes that packaged surface through:

- command `labviewViHistory.openDocumentation`
- history-panel action `Open docs`
- a dedicated documentation webview panel with packaged cross-page navigation

The bundled docs are a version-matched user surface for the installed
extension. They do not replace the repository documentation package as the
authority of record.

## Consequences

Positive:

- users can reach governed guidance from the installed extension without repo
  access
- extension panels can link to packaged local docs instead of repo-only paths
- packaged docs can stay aligned to the published wiki set through one
  machine-readable ledger and one refresh command

Negative:

- the main repo now owns another derived artifact set that must stay refreshed
- documentation publication work must update both the Markdown and JSON
  publication ledgers plus the packaged bundle in the same tranche

## Implementation Surfaces

- `docs/product/wiki-publication-ledger.json`
- `scripts/syncBundledDocs.js`
- `resources/bundled-docs/manifest.json`
- `src/docs/bundledDocumentation.ts`
- `src/docs/bundledDocumentationAction.ts`
- `src/ui/historyPanel.ts`
- `src/commands/openViHistoryCommand.ts`
- `src/extension.ts`
