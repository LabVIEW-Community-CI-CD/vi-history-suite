Purpose

vi-history-suite now keeps one explicit rule for technical and documentation debt:

  • no silent debt

If a future session discovers meaningful debt, it is not allowed to remain only in chat, shell history, or local memory.

Allowed Outcomes

Every discovered debt item must become one of:

  1. retired now
  2. open debt with an owner, evidence set, next gate, and exit criteria
  3. accepted bounded exception with an explicit rationale

That rule applies across technical, documentation, control-plane, benchmark, runtime, evidence, and release debt.

Why The Contract Exists

The repo now carries several long-lived control planes at once:

  • ship and release-readiness control
  • wiki-completion control
  • benchmark-proof control
  • canonical experiment-admission control

Without a separate debt contract, future sessions could still leave known carryover implicit even while those other control planes remain green.

Required Surfaces

The authority repo retains the debt package here:

  • docs/product/debt-retirement-contract.md
  • docs/product/debt-taxonomy.md
  • docs/product/debt-ledger.md
  • docs/product/debt-ledger.json

The machine-readable source of truth is debt-ledger.json.

Required Fields

Every debt item must retain:

  • debt id and title
  • class, status, severity, and contamination risk
  • owner tranche, issue, and execution program
  • authoritative source docs and repo evidence
  • discovered context
  • next gate when the debt is still open
  • exit criteria
  • retirement commit when the debt is already retired
  • accepted-exception rationale when the debt is intentionally not retired yet

Reader Rule

Future sessions should not call work complete while meaningful debt is still known locally but absent from the governed debt ledger.

That is the practical meaning of the contract:

  • retire it
  • ledger it
  • or explicitly accept it as a bounded exception
