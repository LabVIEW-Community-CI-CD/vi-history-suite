Purpose

vi-history-suite treats the multi-report dashboard as a decision-support surface, not as an automated decision-maker.

The review-scenario and decision-record layer exists so a human reviewer can:

  • apply a bounded review scenario to one VI across multiple commits
  • use retained dashboard evidence as the basis for judgment
  • persist a separate human decision record without mutating machine evidence

Scenario Model

The repo currently defines scenario maturity explicitly:

  • draft: modeled but not yet exercised by a governed harness or packet
  • active: queued or partially implemented with a named harness and packet
  • certified: supported by governed evidence and ready for routine human use

Canonical Active Scenario

The currently active canonical scenario is:

  • SCENARIO-VHS-001
  • maturity: active
  • harness: HARNESS-VHS-001
  • repository: ni/labview-icon-editor
  • VI target: Tooling/deployment/VIP_Pre-Install Custom Action.vi
  • minimum commit window: 3
  • minimum comparison pairs: 2

Its decision goal is to help a human reviewer make a bounded decision about one VI after multiple modifications using concentrated comparison-report evidence, instead of relying on a single pairwise report or a raw commit list.

Human Decision Boundary

The dashboard may improve human review decisions, but it does not decide VI correctness automatically.

The human reviewer remains responsible for:

  • final judgment
  • interpretation of binary or visual evidence
  • deciding whether more manual LabVIEW inspection is needed

Decision Record Contract

Decision records are intentionally separate from dashboard packets.

The governed decision-record template currently retains:

  • scenario metadata
  • harness and repository identity
  • VI path
  • commit-window bounds
  • comparison-pair coverage
  • dashboard packet path
  • reviewer identity
  • review question
  • evidence used
  • reviewer outcome
  • reviewer confidence
  • rationale
  • follow-up actions

This separation keeps machine-retained evidence and human judgment from being collapsed into one artifact.

Extension Flow

The extension currently exposes Create decision record when the retained VI review window is large enough.

The current governed flow:

  • requires at least three commits in the retained window
  • derives the active scenario from repository URL plus VI path
  • fails closed when trust, storage, repository URL, scenario match, or scenario contract requirements are not satisfied
  • persists separate decision-record.json and decision-record.md artifacts
  • opens the retained Markdown decision record without mutating the dashboard packet

Future Scenario Direction

The next modeled scenario direction is:

  • SCENARIO-VHS-002
  • maturity: draft
  • focus: high-volume open-source VI review where one VI has many retained modifications and the dashboard must reduce reviewer wear from too many individual pairwise reports

That future path is intended to keep the review surface bounded while making larger commit windows more manageable for expert LabVIEW users.
