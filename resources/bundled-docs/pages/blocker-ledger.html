Purpose

The blocker ledger is the retained ship-control record of formal blockers against the original SHIP-0001 release target.

It answers a bounded question: what explicitly blocked the first immutable release, what evidence closed those blockers, and what remains only as historical control-plane truth.

Current State

The blocker ledger now records:

  • ship id: SHIP-0001
  • lifecycle state: closed
  • release target: v0.2.0
  • active tranche id for that historical ship record: TRANCHE-009
  • active issue id for that historical ship record: ISSUE-0406

The important consequence is that the original first-release blocker set is no longer open.

Retained Blockers

The current retained blockers are closed ship-history records, including:

  • a progress/cancellation/runtime-doctor UX blocker that is now resolved
  • a release-artifact and release-manifest blocker that is now resolved

Each blocker keeps:

  • the criterion it affected
  • the tranche and issue that owned it
  • evidence paths
  • impact
  • the resolution path

Why It Still Matters

Even though the blockers are closed, the ledger still matters because it keeps the release history inspectable.

It prevents future sessions from having to reconstruct:

  • what actually blocked v0.2.0
  • what changed to close those gaps
  • which surfaces were treated as proof

That is especially important now that active work lives in post-release tranches rather than inside the original ship tranche.

Boundary

The blocker ledger is not the same as the active queue.

Use it for:

  • retained release-control history
  • closed ship evidence
  • explanation of why the original ship target became releasable

Use the development queue and current-state surfaces for:

  • the currently active tranche
  • current issue/program ownership
  • post-release direction
