Purpose

The program repo jump surface exists so future sessions can move between the governed CompareVI repos on this machine without depending on chat memory or ad hoc shell history.

The current governed constellation is:

  • vi-history-suite
  • vi-history-suite-source-experiments
  • vi-history-suite.wiki
  • repo-standards-review

Authority Roles

Each repo has a specific role:

  • vi-history-suite: product authority and ship-control repo
  • vi-history-suite-source-experiments: private GitHub experiment mirror for non-authoritative benchmark iteration
  • vi-history-suite.wiki: derived reader surface
  • repo-standards-review: companion assurance skill and standards-review surface

If those repos disagree, the documentation package in vi-history-suite remains the authority of record until the others are aligned.

Governed Map

The machine-readable source of truth is:

  • docs/product/program-repo-jump-map.json

That map retains:

  • governed repo ids
  • authority roles

  • primary entrypoints for each repo

This is the map consumed by the wiki workbench, so wiki staging and bundle sync use the same governed constellation rather than hardcoded sibling guesses.

Local CLI

The local CLI from vi-history-suite gives a deterministic repo summary:

npm run program:repos

Useful variants:

npm run program:repos -- --repo repo-standards-review
npm run program:repos -- --format json

The governed wiki workbench uses the same cross-repo model:

npm run wiki:workbench:doctor

Companion Skill Entry

From the companion assurance skill, the reciprocal resolver is:

python3 scripts/repo_jump.py /home/sveld/code/standards/vi-history-suite --format text

That keeps the cross-repo navigation model anchored in this repo instead of duplicating a second hardcoded constellation.

Boundary

It is not:

  • a runtime-proof lane
  • a release-authority replacement
  • a benchmark-authority replacement

The governed boundary remains:

  • GitLab vi-history-suite: authority
