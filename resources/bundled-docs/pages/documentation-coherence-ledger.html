Purpose

The documentation coherence ledger is the retained proof that the governed docs package still agrees with itself.

It exists so future work does not need to rediscover whether the main documentation surfaces are aligned. Instead of trusting memory, the repo keeps one explicit coherence record that states:

  • which authority surfaces were audited
  • which gates were run
  • which contradictions were resolved
  • which residual risks still remain
  • which documentation move should happen next

What It Audits

The coherence pass covers the main documentation control plane for vi-history-suite, including:

  • ship and release-control docs
  • requirements, RTM, and test plan
  • architecture overview and active ADRs
  • wiki authority, seed, and publication ledgers
  • documentation workbench guidance
  • bundled documentation manifest
  • current-state and related control-plane docs

This matters because the wiki is a derived reader surface. If the main repo docs drift internally, the wiki would widen bad information faster.

Latest Pass

The current retained pass records:

  • date: 2026-04-04
  • repo docs gate: pass
  • repo design gate: pass
  • standards-guided release gate: coverage PASS, cm PASS, req PASS, arch PASS, doc PASS, dod PASS

The intended operating model is simple:

  1. change governed documentation
  2. rerun the docs and design gates
  3. update the coherence ledger if the control plane changed materially
  4. only then widen or refresh wiki content

Resolved Contradictions

The retained ledger currently records a sequence of resolved documentation contradictions, including:

  • docs-gate path resolution and reproducibility issues
  • missing or stale ADR coverage
  • missing wiki-seeding and publication-control surfaces
  • requirements and test-plan drift
  • research-alignment drift
  • post-release control-plane drift
  • missing deterministic wiki-workbench preparation flow

The important point is not the exact count. The important point is that the repo retains a history of why the documentation package became stronger, rather than pretending it was always coherent.

Current Truth

The current coherence position is:

  • no unresolved contradiction is retained across the audited authority stack
  • the docs gate is the first-line regression barrier
  • the wiki workbench is now part of the governed docs system
  • published wiki state also drives the bundled documentation shipped with the extension
  • the cross-repo jump surface keeps authority, experiment, wiki, and assurance-skill roles distinct

That means future wiki work should start from the main docs package, not from source-code browsing or prior chat context.

Residual Risks

The coherence ledger still records bounded external risks rather than claiming perfect certainty.

Current examples include:

  • environment-dependent local Docker proof for the docs-authoring image
  • companion assurance-release publication proof that was not fully confirmed by the local API path
  • a curated research implementation index that is still not a full 1:1 requirement database

Those are not reasons to bypass the docs package. They are reasons to keep the ledger current.

Why It Matters For The Wiki

The coherence ledger is one of the controls that keeps the wiki from becoming a free-form prose surface.

Before wiki widening:

  • the authority stack should already agree
  • the wiki seed plan should identify the next bounded page
  • the wiki publication ledger should reflect what is actually published
  • the workbench should retain publication-prep evidence

That sequence is what makes the wiki a derived publication surface instead of a parallel authority surface.
