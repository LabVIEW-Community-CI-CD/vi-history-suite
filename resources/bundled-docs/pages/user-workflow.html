Preconditions

The current governed workflow assumes:

  • the extension is installed from the preview VSIX or a future tagged release
  • the workspace is trusted
  • the target file is inside an open Git repository
  • the target file is content-detected as a LabVIEW VI

The extension only surfaces VI History for tracked files that satisfy VI detection and have at least two modifying commits.

The installed extension also exposes a first-class documentation command:

  • VI History: Open Documentation

Execution Policy

The current authority package now makes the future execution-mode contract explicit even though it is not implemented in the manifest yet.

The queued policy is:

  • auto / host-only / docker-only

That contract is meant to make host-versus-Docker behavior transparent instead of leaving it implicit in bitness preferences or ambient runtime discovery.

When that tranche lands:

  • compatible host LabVIEW 2026 Q1 x86 or x64 execution remains valid when the selected mode permits host-native launch and the host surface is clean
  • if a conflicting host LabVIEW 2026 session or governed VI Server collision would contaminate host execution, auto requires Docker isolation instead
  • if Docker is required and unavailable, the extension hard-stops with actionable guidance to close the conflicting LabVIEW session or install and enable Docker
  • if Docker execution is selected and the image is missing locally, the extension surfaces visible pull progress; on Windows that means pulling the governed Windows image
  • no selected mode is allowed to silently fall back to a different provider

Primary Review Flow

  1. Right-click an eligible VI and choose VI History.
  2. Review the history panel facts:
    • repository name
    • relative path
    • VI signature
    • retained commit chronology
  3. Use the row actions that match the current evidence state.

The current action model is:

  • Open at commit: open the selected retained revision
  • Copy hash: copy the retained commit hash
  • Open docs: open the bundled user documentation that ships with the installed extension version
  • Generate compare: create retained pair comparison evidence when it does not already exist
  • Refresh compare: rerun comparison generation for a retained pair
  • Open compare: open retained pair comparison evidence when it already exists
  • Diff prev: open retained pair comparison evidence for content-detected VIs when that evidence exists; otherwise the extension fails closed and directs the reviewer to Generate compare

Comparison Report Flow

Comparison-report generation and opening are treated as governed review actions, not ad hoc shell commands.

When a pair comparison is generated or refreshed, the extension retains:

  • the comparison-report packet
  • report metadata
  • the generated NI comparison report when one exists
  • bounded runtime-doctor facts for provider, engine, platform, tool selection, and next action

If the user cancels comparison work before the comparison view opens, the extension returns a stable cancelled outcome instead of opening the view after cancellation.

Dashboard Flow

When a VI has at least three retained commits, the history panel exposes Open dashboard.

The dashboard is the concentrated review surface for one VI across adjacent retained pairs. The current governed dashboard flow:

  • prepares the commit window
  • backfills missing or stale adjacent-pair evidence when needed
  • concentrates retained NI comparison-report metadata across the window
  • finalizes retained dashboard assets
  • opens the dashboard view

The dashboard currently emphasizes:

  • chronology-first pair metadata
  • concentrated comparison-report metadata across the retained window
  • bounded progress during heavier refresh work
  • a bounded current-session ETA during pair preparation
  • retained pair-level ETA accuracy characterization for the current refresh

Decision Record Flow

When a retained review window has at least three commits, the history panel also exposes Create decision record.

That action creates separate human-review artifacts from retained dashboard evidence. The decision record is intentionally separate from the dashboard and comparison-report evidence so human judgment does not overwrite machine-retained facts.

Trust, Progress, And Cancellation

The current workflow is explicitly trust-gated.

  • comparison-report actions fail closed in untrusted workspaces
  • dashboard actions fail closed in untrusted workspaces
  • the history-panel command flow surfaces stable trust warnings when an already opened panel later reaches a trust-gated action

Long-running comparison and dashboard actions execute with bounded progress and cancellation support. Cancellation is intended to preserve already retained evidence instead of discarding it silently.

That same transparency rule now also governs the queued execution-mode work: future provider selection and Docker acquisition progress are expected to be visible in front-facing UX rather than discoverable only from shell output.

Bundled Documentation

The extension packages a version-matched bundled documentation surface so reviewers do not need repo access just to read guidance.

That packaged surface can be opened from:

  • the Command Palette via VI History: Open Documentation
  • the history panel via Open docs
