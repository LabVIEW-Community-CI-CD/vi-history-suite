Preconditions

The current governed workflow assumes:

  • the extension is installed from the preview VSIX or a future tagged release
  • the workspace is trusted
  • the target file is inside an open Git repository
  • the target file is content-detected as a LabVIEW VI

The extension only surfaces VI History for tracked files that satisfy VI detection and have at least two modifying commits.

The installed extension also exposes a first-class documentation command:

  • VI History: Open Documentation

Execution Policy

The current authority package now makes the broader execution-mode contract explicit, and the installed extension already exposes the first execution-mode slice in the manifest and runtime selector.

The current installed setting is:

  • viHistorySuite.executionMode

with these governed values:

  • auto / host-only / docker-only

The currently implemented slice now makes host-versus-Docker behavior explicit at the provider-selection boundary instead of leaving it implicit in bitness preferences or ambient runtime discovery.

Current implemented truth:

  • the manifest exposes auto, host-only, and docker-only
  • host-only rejects Docker instead of silently falling back to it
  • docker-only rejects host-native execution instead of silently falling back to it
  • on Windows, auto now stays host-native when the selected compatible host runtime surface is clean instead of using Docker by habit
  • the installed selector now derives the selected LabVIEW.ini and governed VI Server port from the selected host runtime before final provider choice
  • on Windows, contaminated host-runtime surfaces now route to Docker when the governed provider is available and hard-stop when that Docker escape path is unavailable
  • when Windows Docker evaluation is in play, the selector now validates Docker CLI availability, daemon reachability, active container mode, and governed image presence before the Windows provider is selected or rejected
  • when Windows container execution is selected and the governed image is missing, comparison-report generation now surfaces visible governed image-pull progress before packet persistence and runtime launch
  • retained runtime-doctor and packet surfaces now carry acquisition state and acquisition-failure hard stops explicitly
  • the history panel now also retains the latest compare-runtime summary with selected provider, rejected-provider reasons, execution mode, acquisition state, and next action
  • the history panel now also mirrors live governed compare-runtime progress while comparison generation is selecting a runtime, acquiring the Windows image, or executing the LabVIEW runtime
  • blocked or failed compare actions now also emit one concise mode-aware warning using that same retained runtime truth

The remaining queued contract is:

  • the extension first resolves one canonical effective execution request from the selected mode, host-runtime facts, and Docker capability facts

  • compatible host LabVIEW 2026 Q1 x86 or x64 execution remains valid when the selected mode permits host-native launch and the host surface is clean

  • in auto, a clean compatible host stays host-native and does not acquire Docker just because Docker happens to be installed

  • if a conflicting host LabVIEW 2026 session or governed VI Server collision would contaminate host execution, auto requires Docker isolation instead

  • the governed host conflict is tied to the selected LabVIEW.ini and its derived VI Server port, not to one assumed default port

  • if Docker is required and unavailable, or if Docker is not Windows-container- capable on Windows, the extension hard-stops with actionable guidance to close the conflicting LabVIEW session or install, enable, or switch Docker

  • when Docker is evaluated on Windows, the retained runtime-doctor and packet surfaces now show whether Docker CLI was available, whether the daemon was reachable, which container mode was active, and whether the governed image was already present locally

  • the current comparison-report path now surfaces visible pull progress when Windows container execution still requires the governed Windows image

  • the current history-panel compare-runtime block now mirrors those governed runtime/acquisition stages while the action is still running

  • reopening VI History now seeds that compare-runtime block from the last retained tracker-backed compare result instead of resetting it to idle

  • fuller front-facing provider/acquisition transparency beyond the current progress, compare-warning, compare-success, reopened history-panel, runtime-doctor, and retained-packet surfaces remains open under PROGRAM-0005

  • host-only hard stops tell the user to close LabVIEW, resolve the governed port conflict, correct the selected host runtime, or change execution mode

  • no selected mode is allowed to silently fall back to a different provider

Primary Review Flow

  1. Right-click an eligible VI and choose VI History.
  2. Review the history panel facts:
    • repository name
    • relative path
    • VI signature
    • retained commit chronology
  3. Use the row actions that match the current evidence state.

The current action model is:

  • Open at commit: open the selected retained revision
  • Copy hash: copy the retained commit hash
  • Open docs: open the bundled user documentation that ships with the installed extension version
  • Generate compare: create retained pair comparison evidence when it does not already exist
  • Refresh compare: rerun comparison generation for a retained pair
  • Open compare: open retained pair comparison evidence when it already exists
  • Diff prev: open retained pair comparison evidence for content-detected VIs when that evidence exists; otherwise the extension fails closed and directs the reviewer to Generate compare

Comparison Report Flow

Comparison-report generation and opening are treated as governed review actions, not ad hoc shell commands.

When a pair comparison is generated or refreshed, the extension retains:

  • the comparison-report packet
  • report metadata
  • the generated NI comparison report when one exists
  • bounded runtime-doctor facts for provider, engine, platform, tool selection, and next action

If the user cancels comparison work before the comparison view opens, the extension returns a stable cancelled outcome instead of opening the view after cancellation.

Dashboard Flow

When a VI has at least three retained commits, the history panel exposes Open dashboard.

The dashboard is the concentrated review surface for one VI across adjacent retained pairs. The current governed dashboard flow:

  • prepares the commit window
  • backfills missing or stale adjacent-pair evidence when needed
  • concentrates retained NI comparison-report metadata across the window
  • finalizes retained dashboard assets
  • opens the dashboard view

The dashboard currently emphasizes:

  • chronology-first pair metadata
  • concentrated comparison-report metadata across the retained window
  • bounded progress during heavier refresh work
  • a bounded current-session ETA during pair preparation
  • retained pair-level ETA accuracy characterization for the current refresh

Decision Record Flow

When a retained review window has at least three commits, the history panel also exposes Create decision record.

That action creates separate human-review artifacts from retained dashboard evidence. The decision record is intentionally separate from the dashboard and comparison-report evidence so human judgment does not overwrite machine-retained facts.

Trust, Progress, And Cancellation

The current workflow is explicitly trust-gated.

  • comparison-report actions fail closed in untrusted workspaces
  • dashboard actions fail closed in untrusted workspaces
  • the history-panel command flow surfaces stable trust warnings when an already opened panel later reaches a trust-gated action

Long-running comparison and dashboard actions execute with bounded progress and cancellation support. Cancellation is intended to preserve already retained evidence instead of discarding it silently.

That same transparency rule now governs the current execution-mode work: provider selection, acquisition state, and governed Windows image-pull progress are no longer meant to be discoverable only from shell output.

Bundled Documentation

The extension packages a version-matched bundled documentation surface so reviewers do not need repo access just to read guidance.

That packaged surface can be opened from:

  • the Command Palette via VI History: Open Documentation
  • the history panel via Open docs
