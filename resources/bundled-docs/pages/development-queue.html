Purpose

The development queue is the retained ordered list of implementation tranches for vi-history-suite.

Its job is to keep one explicit answer to a simple question: what is active now, what is already done, and what is only queued.

Queue Shape

The current queue includes:

  • completed tranches for report planning, runtime selection, live execution, Windows containerization, dashboard review, decision records, runtime-doctor UX, and SemVer releaseability
  • one queued tranche for further progress-surface uplift
  • one active post-release tranche for the public facade release kit and host-machine acceptance work
  • one queued follow-on tranche for repeatable Windows and Linux benchmark proof
  • one queued follow-on tranche for post-release sustainment and release cadence
  • one queued follow-on tranche for extension execution flexibility and runtime acquisition UX

Why The Queue Matters

The queue is not just a roadmap. It is part of the control plane.

It keeps:

  • one active tranche at a time
  • landed work distinguishable from merely planned work
  • issue linkage explicit when a tranche is tied to a formal issue
  • post-release work separate from the already-closed ship target

That is what prevents the repo from collapsing back into open-ended iteration.

Relationship To Ship Control
